# docker-minecraft

Ванильный сервер Minecraft, который запускается в Docker. В репозитории лежат
и конфиг запуска, и сами данные сервера (мир, настройки, whitelist/ops).

Текущая версия: **26.2** (требует Java 25 — образ `eclipse-temurin:25-jre`).

## Что нужно

Только [Docker](https://docs.docker.com/get-docker/) с Docker Compose v2.
Java на хосте не нужна — она внутри контейнера.

## Запуск

```bash
docker compose up -d
```

Сервер поднимется на порту `25565`. Первый старт после обновления версии
занимает дольше обычного — сервер конвертирует мир.

Логи:

```bash
docker compose logs -f
```

Консоль сервера (ввод команд вроде `op`, `whitelist add`, `stop`):

```bash
docker attach minecraft
```

Выйти из консоли, **не** останавливая сервер: `Ctrl+P`, затем `Ctrl+Q`.
Нажатие `Ctrl+C` внутри attach убьёт сервер.

Остановка:

```bash
docker compose stop
```

Compose ждёт до 60 секунд, чтобы сервер успел сохранить мир. Не убивайте
контейнер через `kill` — можно потерять последние сохранения чанков.

## Обновление сервера

```bash
./update-server.sh          # последний релиз
./update-server.sh 1.21.8   # конкретная версия
```

Скрипт сам:

1. берёт манифест версий с серверов Mojang;
2. качает `server.jar` нужной версии;
3. **проверяет SHA1** — если не совпал, файл удаляется и обновление прерывается;
4. кладёт копию в `server/versions/<версия>/` и подменяет `server/server.jar`;
5. записывает версию в `server/.version` (повторный запуск ничего не делает).

Полный цикл обновления:

```bash
docker compose stop
tar czf world-backup-$(date +%F).tar.gz server/1488   # бэкап мира
./update-server.sh
docker compose up -d
docker compose logs -f                                 # смотрим, что мир сконвертировался
```

### Важно про конвертацию мира

Обновление версии **необратимо для мира**. При первом запуске на новой версии
сервер конвертирует папку мира и меняет её структуру — например, при переходе
с 1.20.4 на 26.2 `region/`, `entities/`, `poi/` уезжают внутрь `dimensions/`,
а `playerdata/`, `advancements/`, `stats/` объединяются в `players/`.

Откатиться на старую версию с уже сконвертированным миром нельзя — только
восстановить мир из бэкапа. Поэтому бэкап перед обновлением обязателен, а не
«по желанию».

Старые версии jar остаются в `server/versions/`, так что вернуться на прежнюю
версию сервера (вместе с бэкапом мира) можно вручную:

```bash
cp server/versions/1.20.4/server-1.20.4.jar server/server.jar
echo 1.20.4 > server/.version
```

## Память

Лимиты заданы в `docker-compose.yml`:

```yaml
command: java -Xms2G -Xmx4G -jar server.jar nogui
```

`-Xmx` — потолок, `-Xms` — сколько занять сразу. Правьте под свою машину;
для пары игроков хватает `-Xms1G -Xmx2G`.

## Настройки сервера

Основное — в `server/server.properties` (применяется после перезапуска):

| Параметр | Сейчас | Что делает |
|---|---|---|
| `level-name` | `1488` | папка мира внутри `server/` |
| `max-players` | `20` | лимит игроков |
| `difficulty` | `easy` | сложность |
| `online-mode` | `false` | **выключена** проверка лицензии Mojang (см. ниже) |
| `white-list` | `false` | доступ без белого списка |
| `server-port` | `25565` | порт (менять и в `docker-compose.yml`) |

## Структура репозитория

```
docker-compose.yml       запуск сервера
update-server.sh         обновление до нужной версии
server/
  server.jar             текущий jar
  .version               какая версия установлена
  versions/              скачанные версии (1.19.3, 1.20.4, 26.2)
  server.properties      настройки
  1488/                  мир
  ops.json               администраторы
  whitelist.json         белый список
  banned-players.json    баны
  eula.txt               принятый EULA
```

`server/logs/` и прочий рантайм-мусор в git не попадают (см. `.gitignore`).

## На что стоит обратить внимание

- **`online-mode=false`** — сервер не проверяет аккаунты, подключиться можно
  под любым ником. Для сервера, открытого в интернет, включите `online-mode=true`
  или хотя бы `white-list=true`.
- **`rcon.password` лежит в репозитории открытым текстом** в `server.properties`.
  Сам RCON сейчас выключен (`enable-rcon=false`), так что это не эксплуатируется,
  но пароль стоит сменить перед включением RCON — и учтите, что старое значение
  останется в истории git.
- Мир (`server/1488/`, ~560 МБ) хранится прямо в git. После конвертации мира
  на новую версию diff будет огромным — это ожидаемо.
